# Changelog v0.2.1

## Bug 修复

### LOG_LEVEL 环境变量修复

**问题**: `LOG_LEVEL` 环境变量在 `.env.sample` 和文档中有定义，但代码中硬编码为 `INFO`，导致配置不生效。

**修复**: 
- `src/python_code_sandbox_mcp/server.py`: 
  - 将 `load_dotenv()` 和 logging 配置移到其他导入之前
  - 从环境变量读取 `LOG_LEVEL`
  - 使用 `getattr(logging, LOG_LEVEL, logging.INFO)` 安全获取日志级别
- `examples/utils.py`: 所有 `get_server_params*` 函数新增 `LOG_LEVEL` 环境变量传递

**使用方式**:
```bash
# .env 文件
LOG_LEVEL=DEBUG

# 或环境变量
export LOG_LEVEL=DEBUG  # Linux/Mac
set LOG_LEVEL=DEBUG     # Windows CMD
$env:LOG_LEVEL="DEBUG"  # Windows PowerShell
```

支持的日志级别: `DEBUG`, `INFO`, `WARNING`, `ERROR`

**MCP 客户端配置注意事项**:
当通过 stdio 方式启动 MCP 服务器时，需要在 `env` 参数中显式传递 `LOG_LEVEL` 环境变量：

```python
StdioServerParameters(
    command="uv",
    args=[...],
    env={
        "LOG_LEVEL": os.environ.get("LOG_LEVEL", "INFO"),
        # ... 其他变量
    }
)
```
