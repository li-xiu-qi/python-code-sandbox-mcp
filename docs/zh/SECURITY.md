# 安全考量

## 隔离模型

### Docker 容器
沙盒使用标准的 Docker 容器进行隔离。这提供了与主机系统的强大分离层，但它不是虚拟化级别的安全边界（如 VM）。

- **文件系统**: 除非显式挂载，否则容器无法访问主机文件系统。目前，服务器默认 **不** 挂载任何主机目录。
- **网络**: 容器使用默认的网桥网络创建。它们 **拥有** 互联网访问权限（`pip install` 需要），但未经特殊配置无法轻松访问主机机器上运行在 `localhost` 的服务。

## 资源限制

为了防止失控脚本使主机崩溃，`docker_utils.py` 默认强制执行以下限制：

- **内存**: 2GB (`mem_limit="2g"`)
- **CPU**: 1 个核心的 50% (`cpu_period=100000`, `cpu_quota=50000`)
- **磁盘**: 服务器代码未强制执行显式配额。容器继承默认的 Docker 存储限制（Docker Desktop 上通常为每个容器 **20GB**）。鉴于容器的临时性质和后台清理机制，在正常使用下不太可能耗尽磁盘。

## 最佳实践

1.  **临时使用**: 始终将沙盒视为临时的。不要在其中存储关键数据。
2.  **代码注入**: 服务器使用 Base64 编码将代码传输到容器。这防止了基本的 shell 注入攻击，但运行在容器 *内部* 的恶意 Python 代码仍可能尝试利用内核漏洞（尽管在最近的 Docker 版本中不太可能）。
3.  **网络访问**: 请注意，在沙盒中运行的代码可以发出出站 HTTP 请求（例如 `requests.get('http://malicious-site.com')`）。
