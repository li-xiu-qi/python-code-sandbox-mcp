# Changelog v0.2.1

## Bug Fixes

### LOG_LEVEL Environment Variable Fix

**Issue**: The `LOG_LEVEL` environment variable was defined in `.env.sample` and documentation, but hardcoded as `INFO` in the code, making the configuration ineffective.

**Fix**:
- `src/python_code_sandbox_mcp/server.py`:
  - Moved `load_dotenv()` and logging configuration before other imports
  - Read `LOG_LEVEL` from environment variable
  - Used `getattr(logging, LOG_LEVEL, logging.INFO)` for safe log level retrieval
- `examples/utils.py`: Added `LOG_LEVEL` environment variable passing to all `get_server_params*` functions

**Usage**:
```bash
# .env file
LOG_LEVEL=DEBUG

# Or environment variable
export LOG_LEVEL=DEBUG  # Linux/Mac
set LOG_LEVEL=DEBUG     # Windows CMD
$env:LOG_LEVEL="DEBUG"  # Windows PowerShell
```

Supported log levels: `DEBUG`, `INFO`, `WARNING`, `ERROR`

**MCP Client Configuration Note**:
When starting the MCP server via stdio, you need to explicitly pass the `LOG_LEVEL` environment variable in the `env` parameter:

```python
StdioServerParameters(
    command="uv",
    args=[...],
    env={
        "LOG_LEVEL": os.environ.get("LOG_LEVEL", "INFO"),
        # ... other variables
    }
)
```
